# Versioning and Release Policy

All components begin at `0.1.0`. Each repository owns its version and release notes after the initial publication.

- Patch releases contain compatible fixes and documentation corrections.
- Minor releases may add capabilities without requiring a coordinated major release.
- Major releases may change public contracts, profile schemas, or supported API behavior.
- A profile release must declare its profile format, language coverage, fixtures, and compatibility with the minimum API engine version.
- Release tags use the repository version, for example `v0.1.0`.

The initial publication is an early release. A green build does not imply complete language semantics or production readiness for every deployment model.
